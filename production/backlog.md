## Current state (read this first)

- The game was rebranded from "Board of Realities" to **Capital Syndicate: Financial Reality Engine** - a dark neon, cyberpunk-Tokyo financial sandbox RPG.
- **By current direction, only the Finance world is in play - and now it's the only thing `OverworldScene.js` builds at all.** The old approach kept Hunter's Rift and King of Games sealed off but still drawn (terrain, buildings, trees, wandering NPCs, rift portals) with `isBlockedTile` just blocking entry - which meant walking near the map edges, you could see both other worlds sitting right there, plus a "Domino City Gate" marker, even though none of it was enterable. QA caught this ("not a full world of finance, there are still other 2 worlds in the game") so `OverworldScene.js` was rewritten to only build a single self-contained, fully-walled 26x20 Finance map - no corridors, no adjacent regions, no gate markers. Hunter's Rift/King of Games/Domino City's *feature code* (modals, dialogue, monsters, npc rosters under `src/features/hunter/`, `src/features/yugioh/`, `src/features/domino/`, plus `DominoWorldScene.js`) is untouched and still there for a future revival - it's just that nothing in the overworld links to it anymore (`WorldScreen.jsx` still imports and wires up all those modals, but the interact events that would open them can no longer fire). To bring a world back, it needs to be re-added to `OverworldScene.js`'s generation (layout/buildings/NPCs/zones) from scratch or restored from git history (last present as of commit `ec04608`), not just un-hidden.
- `WelcomeScreen.jsx`'s dev-jump menu already only lists Capital Syndicate (verified in this pass); the other options are commented out, not deleted.
- The previous 4-world layout used one continuous master grid (`OverworldScene.js`) rather than 4 separate Phaser scenes; that concept is gone now that only Finance exists. Domino City used to be its own scene, entered through a gate like walking into a building - the gate is gone along with the rest of the non-Finance map, so `DominoWorldScene.js` is currently unreachable (see above).
- **Character Creator and the dice-roll screen are gone.** "New Game" on the welcome screen goes straight into the world with one fixed character (`startNewGame()` in `useGameStore.js`). There's only one world and one path in right now, so those screens had nothing left to choose between.
- Finance world is now a **4-district map**: Financial District, Commercial District, Underground District, Government & Cultural District (see `FINANCE_BUILDINGS` in `OverworldScene.js`, and `districtBuildings.js` for the buildings' in-game actions).
- Core loop: a Day Counter with an "End Day" button (`endDay()` in the store) that ticks the market, rolls a news headline, and cools down Heat. Win condition is **$1,000,000,000 net worth** (`NET_WORTH_WIN_TARGET` in `marketData.js`).
- Tycoon bosses: Biffle, Vanderbilt, Rusk, and Howard Marks (added this round - see `production/finance-world-reference.md` for his real-world grounding). A roster of 46 more real-world finance figures is planned as ambient NPCs but **not yet implemented** - see `production/finance-npc-roster-50.md` for the full list and which 4 are bosses vs. which 46 are ambient-only.
- Voice lines: 20 named characters have real generated voice-over via `scripts/generate-voice-lines.mjs` (OpenAI TTS, `gpt-4o-mini-tts`). **Requires your own `OPENAI_API_KEY` in a root `.env` file** (gitignored, never committed) to regenerate or add more.
- A live NPC free-text chat backend exists at `backend/` (FastAPI + OpenAI `gpt-4o-mini`). Needs the same `OPENAI_API_KEY` and must be run as its own process alongside `npm run dev` - see `backend/README.md`. Content boundary: romantic actions cap at a kiss, gated by relationship tier, enforced in the system prompt.
- Reference docs for lore/world-building grounding live in `production/`: `solo-leveling-reference.md` (Hunter, currently sealed but kept for when it's revisited), `finance-world-reference.md`, `finance-npc-roster-50.md`, `yugioh-world-reference.md` (scoped strictly to the original Yugi-protagonist era), `world-bible.md`.
- **The Stock Exchange is now a walk-in building with a real mini-game, not an instant popup.** Walking up to it and pressing E no longer opens `StockExchangeModal` directly - it swaps `OverworldScene.js` into a small indoor `stockExchangeInterior` zone (same in-scene zone-swap technique `DominoWorldScene.js` already used for its own rooms; see `loadZone()`/`ZONES`/`currentZoneId` in `OverworldScene.js`). Walk up to the "Trading Floor" desk inside and press E to open the same modal as before. Inside `StockExchangeModal.jsx`, the plain buy/sell buttons were replaced by `TradeMeter.jsx`: a timed marker sweeps across a bar with a randomly-placed "sweet zone" - executing inside it gets a price discount (buy) or bonus (sell); missing it just fills at plain market price (no fail state). `useGameStore.js`'s `buyStock`/`sellStock` both gained an optional `priceMultiplier` param (default 1) to support this - fully backward compatible. The other 18 buildings are untouched (still instant modals). This was intentionally scoped to Stock Exchange only, as a first slice to prove out the pattern - see the next item for what's deferred.
- **Map expanded and all 18 remaining buildings given walk-in interiors** (this was the item deferred above; both are done now). `OverworldScene.js`'s `FINANCE_BUILDING_DEFS` no longer hand-places tile coordinates - `layoutFinanceMap()` packs each district's buildings left-to-right into its own row band (wrapping to a second row per band as needed) and computes the map size from that, so buildings can never overlap each other or the border by construction (checked with a standalone overlap script before wiring it in, not eyeballed). This produced a 40x33 map (up from 26x20) with real 4-tile gaps between buildings, instead of the previously-referenced "~40x46 Plan-agent layout" - that file never actually existed on disk, so 40x33 is what an overlap-checked packer actually produces, not a target that was hit. Tree count scaled from 32 to 80 to match the larger walkable area. Spawn point moved to `{col:7, row:1}` (a clear buffer row above the Financial District band); the vertical street col 7 was verified (not eyeballed) to fall inside every band's first inter-building gap regardless of that band's first building's width.
- Every building except Stock Exchange (which keeps its bespoke trading-floor room) now walks the player into a shared-template interior instead of popping an instant modal: `INTERIOR_TEMPLATES` (`cryptoHQ`, `tycoonOffice`, `officeA`, `officeB`, `amenity`) hold just a floor palette + desk color/label, and `BUILDING_INTERIOR_TEMPLATE` maps each building id to one - Crypto HQ alone gets `cryptoHQ`, the 4 tycoon HQs (Biffle/Vanderbilt/Rusk/Howard Marks) share `tycoonOffice`, Bank+Real Estate Agency share `officeA`, Corporate Holdings+VC Hub share `officeB`, and the 9 remaining district-config buildings (casino, arcade, hotel, crimeAlley, blackMarket, callCenterOps, parliament, park, temple) share `amenity`. All of them reuse the same 12x9 room shape and the same `drawInteriorRoom()` draw call (factored out of what used to be Stock-Exchange-only code) and the same generic `buildingInterior` zone id - only `stockExchangeInterior` stays a separate, bespoke zone. Critically, the desk inside every one of these rooms emits the exact same `{type:'building', id, npcId}` interact payload the building used to emit instantly on contact, so **no changes were needed in `WorldScreen.jsx` or any modal** - confirmed by reading its `activeModal?.type === 'building' && activeModal.id === ...` / `DISTRICT_BUILDING_IDS.includes(...)` / `activeModal.npcId` branches before making this change, not just assumed.
- **Not yet manually playtested** - `npm run build` and `npm run lint` are clean and the overworld was visually verified in a real browser (player renders correctly on the new map, buildings are visibly spaced out), but walking into one of the 18 newly-interior'd buildings and confirming the desk opens the right modal has not been done - the automated browser tool's synthetic WASD key presses didn't register as movement in Phaser's keyboard polling (a tool limitation seen before, not a code issue - `tryStartStep()` doesn't require the key to be held), so this needs a real manual pass in the browser.

## Known environment gotchas

- No automated test coverage anywhere (no test files; `npm run lint` is oxlint only) - all regression checking is manual playtesting or live browser verification.
- If you're testing via a headless/automated browser, `document.hidden`/`visibilityState` can end up `"hidden"` even when the tab looks active, which suspends Phaser's `requestAnimationFrame` loop - movement/animation will look completely frozen even though the underlying logic is correct. Verify by grabbing the scene instance and manually calling `tileMover.update(delta, direction)` a few times rather than assuming it's broken.
- Git commits need `user.name`/`user.email` configured locally (`git config --global ...`) - a fresh machine won't have this set.
