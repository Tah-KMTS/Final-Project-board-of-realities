# NPC Chat Backend

FastAPI service that powers the free-text NPC interaction feature. It takes
what the player typed at an NPC and returns a live, in-character reply
generated by `gpt-5.6-luna` (via OpenAI's `/v1/responses` endpoint - this
project's key has no chat-completions/gpt-4o access, only Responses), instead
of canned/keyword-matched dialogue.

For the Capital Syndicate roster (finance titans, crime syndicate,
presidents, Fed/FTC chairmen, agency heads) the frontend also sends a
`character` payload built from the game's own roster + biography data
(`characterLookup.js` + `characterBiographies.js`), so the persona is
generated from real data instead of a second hand-written copy per
character. The reply also comes back with a persuasion verdict - `agreed`
and `relationshipDelta` - decided by the model in character, not scripted;
`NamedNpcModal.jsx` applies the delta to that NPC's relationship meter.
Worlds that don't send `character` (Hunter's Rift, King of Games) fall back
to the hand-authored `NPC_PERSONAS` dict, unchanged from before.

## One-time setup

```
pip install -r backend/requirements.txt
```

The server reads `OPENAI_API_KEY` from the project's existing **root**
`.env` file (not a separate `backend/.env` - don't create one). The key
never reaches the browser; it's only ever used inside this Python process.

## Running (dev)

Board of Realities' local dev now requires **two processes running at the
same time**:

```
# Terminal 1 - frontend (Vite), http://localhost:5173
npm run dev

# Terminal 2 - backend (FastAPI), http://localhost:8079
npm run dev:backend
# equivalent to: uvicorn backend.main:app --reload --port 8079
# (not port 8000 - that's commonly already taken by other local services)
```

CORS is configured to allow requests from `http://localhost:5173` only. If
the backend isn't running, the frontend's NPC chat input still works - it
just shows a graceful fallback line instead of a generated reply (see
`src/utils/npcChatClient.js`).

## Endpoint

`POST /npc-interact`

```json
{
  "npcId": "vanderbilt",
  "playerText": "Give me free shares in your railroad.",
  "relationshipTier": 45,
  "conversationHistory": [
    { "role": "player", "text": "hi" },
    { "role": "npc", "text": "State your business." }
  ],
  "character": {
    "id": "vanderbilt",
    "name": "Cornelius Vanderbilt",
    "title": "Gilded Age Titan",
    "category": "Financial Titan",
    "netWorth": 200000000000,
    "personalBio": "Railroad and shipping monopolist...",
    "age": 82,
    "maritalStatus": "Widowed"
  }
}
```

`character` is optional - omit it for Hunter's Rift/King of Games NPCs, which
still use the hand-authored personas.

Returns:

```json
{ "reply": "...", "agreed": false, "relationshipDelta": -1 }
```

`agreed`/`relationshipDelta` are always populated (default `false`/`0` when
there's nothing to agree to), decided by the model from the character's
actual personality and the relationship tier - never scripted or random.

`GET /health` reports `{"status": "ok", "hasApiKey": true|false}` for a
quick sanity check that the root `.env` was picked up.
